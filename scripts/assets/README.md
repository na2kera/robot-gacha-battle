# U8 カプセル工房アセット

`docs/phase4-plan.md` のアセット節を正とする、独自の玩具工房デザイン。
既存の画像・生成スクリプト・manifest は存在しなかったため新規作成。
ゲーム側の読み込み実装は U9 に委ね、client/・server/ は変更しない。

## 再生成

前提: Node.js 22.12 以降、ImageMagick 7 (`magick`)、librsvg (`rsvg-convert`)、日本語フォント、およびこのリポジトリの既存 npm 依存（実測 JSON の整形に既存の Prettier を使用）。
この環境では Hiragino Maru Gothic ProN を使用。別環境では Noto Sans CJK JP / Noto Sans JP にフォールバックするため、同一のロゴを再生成するには同一フォントが必要。
追加の npm 依存や画像 API キーは不要。

リポジトリ直下で:

```sh
node scripts/assets/generate.mjs
node scripts/assets/verify.mjs
npx prettier --check scripts/assets/*.mjs scripts/assets/README.md public/img/manifest.json
npx eslint scripts/assets/*.mjs
npm run build
```

生成コマンドはこのディレクトリが所有する出力 PNG・manifest・確認画像を再作成する。
検証コマンドは実際の PNG をデコードし、寸法・キー・ファイル名・透過・色数・ボディの外接寸法と衝突円・銃口の +x 端・タイルの対向辺を検証し、`measurements.json` を更新する。
検証結果 JSON には全 62 ファイルの実測サイズ、色数、alpha 外接矩形を列挙する。

赤い正面パーツだけを既存の青い PNG から再生成する場合は `node scripts/assets/generate-red-parts.mjs` を実行する。manifest も更新する。通常の `generate.mjs` も同じ処理を呼び出す。共通パレットの main / dark / hi をそれぞれ青から赤へ完全一致で置換し、それ以外の色・形状・alpha を維持する。`verify.mjs` は12枚すべての RGBA を元画像と比較して検証する。

## 造形案と画素整理

1. 組み込み画像生成ツールに `source/concept-prompt.txt` を入力して単一の造形検討シートを生成。採用案を `source/concept.png` に保存した。
2. 丸い装甲、クリーム色のバンパー、金色の留め具、ホバーポッド・二足・キャタピラの違いを採用。案の左右チーム色の混在や背景効果は採用しない。
3. `generate.mjs` で造形を整数座標のピクセルに描き直す。概念画像を直接縮小・切り抜きする方式ではなく、48px の共通座標系、固定パレット、二値 alpha（カプセル上殻とロゴは除く）を保証する方式。Node の RGBA バッファを一時ファイル経由で ImageMagick に渡して透過 PNG に変換する。一時 RGBA ファイルだけは変換後に除去する。標準入力経由での変換はこの環境でタイムアウトしたため採用しない。
4. 正面パーツは独立した正面図を 48px グリッドに描き、最近傍で 2 倍にする。見下ろし層を流用して正面図に見せない。
5. ロゴだけは `source/logo.svg` の実テキスト「ロボット」「ガチャバトル」を上下二段に組み、`rsvg-convert` で 640×200 PNG にする。ロゴのみアンチエイリアスあり。
6. カプセルの初回案は不採用。組み込み画像生成ツールで再検討した `source/capsule-revision-concept.png` と `source/capsule-revision-prompt.txt` を新しい造形案として保存。薄いミント色の半透明ドームと黄色い不透明な下殻を採用し、中央ボタン・帯・チーム色を除いた。初回の案は制作履歴として保存している。

造形案の生成は確率的で、同じプロンプトでも同一画像にはならない。最終アセットは保存した案を参照してコード化済みで、再生成時には画像生成ツールを呼ばない。生成案の再検討には組み込み画像生成ツールを使い、プロンプトと採用画像を保存してから描画定義を更新する。

## 仕様と座標

- 出力は `public/img/` のみ。manifest は `{"images":{"key":"img/key.png"}}`。public/assets/ は使わない。
- ID は shared/parts.ts の定義を読み取る。コアは `core_vital / core_boost / core_power`。
- 見下ろし層の中心は連続座標 `(24,24)`、右向きが正面。ピクセルの面積は `[x,x+1) × [y,y+1)` と解釈する。
- 描画順は脚 → ボディ → コア → 武器。コアは `(24,24)` を中心に約12pxの炎（火力）・二重の矢羽（機動）・盾（耐久）を描く。武器とコアの不透明画素が重ならないことを検証する。
- 武器層のみ64×48px。他の見下ろし層は48×48px。全層の基準点は `(24,24)` のまま。武器の右端はマシンガン・大砲が `x=59`（半開区間の右端）、ショットガンが `x=55`。ヘビーの右端 `x=47` からそれぞれ12px・12px・8px出る。マシンガンは細い2連、ショットガンは太く短い銃身、大砲は太く長い銃身。
- manifest は幅などのメタデータを追加せず、既存のキー名とパスを維持する。利用側でテクスチャ原点を正規化する場合、武器は `(24/64, 24/48)`、他層は `(0.5,0.5)` にする必要がある。この作業では client/・server/ を変更しない。
- ボディは alpha の外接矩形で light=32×32、standard=38×38、heavy=46×46。外周の各ピクセル中心は判定円の内側。
- パレットは青 #4C8DFF、赤 #FF5C5C、濃紺 #172333、クリーム #FFF3DC、金 #FFD166 と少数の陰影色。ロゴとカプセル以外は半透明なし。
- カプセルは128×128px。上殻は薄いミント色の実際の半透明画素（単なる塗り色ではない）、下殻は #FFD166 系で不透明。閉じた状態では小さな無彩色の玩具パーツが薄く透ける。開いた状態は上下の殻を分離し、間に透明な空隙を設ける。共通演出なので青赤のチーム色は使わない。拡大は最近傍、確認画像への合成は source-over で透過を保持する。
- 背景タイルは全面不透明。対向する端の画素を一致させた周期模様。パーツ類は透明背景。
- `stamp_win` はトロフィー・月桂冠の図柄。勝利の日本語文言はゲーム側の UI に任せる。
